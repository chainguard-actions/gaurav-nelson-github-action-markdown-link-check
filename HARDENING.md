## Findings Fixed

### github-env-injection (severity: high)

In entrypoint.sh's check_errors() function, the output of `cat error.txt` is written directly to $GITHUB_ENV without sanitization (`tr -d '\n\r'`). The error.txt file contains markdown-link-check output which includes URLs and link text from checked markdown files — content that can be attacker-controlled via pull request submissions. The heredoc pattern used (`echo "MLC_OUTPUT<<EOF" >> "$GITHUB_ENV"` / `cat error.txt >> "$GITHUB_ENV"` / `echo "EOF" >> "$GITHUB_ENV"`) is also vulnerable to heredoc injection: if error.txt contains a line consisting solely of `EOF`, the heredoc terminates early and any subsequent lines in error.txt are interpreted as new GITHUB_ENV assignments, allowing an attacker to inject arbitrary environment variables into the runner.

### script-injection (severity: high)

Sub-rule (b): The shell variable $COMMAND is expanded unquoted in `$COMMAND &>> error.txt || true`. This variable is assembled from `${FIND_CALL[*]}` which incorporates user-controlled action inputs including BASE_BRANCH ($7 / inputs.base-branch), FILE_EXTENSION ($8 / inputs.file-extension), and FOLDER_PATH ($4 / inputs.folder-path). Unquoted expansion of $COMMAND allows word splitting and shell metacharacter injection (e.g., semicolons, pipes, backticks) from those attacker-controlled values.

Locations:

### Iteration 1

**Fixes applied:** github-env-injection, script-injection

**Notes:**

Fixed two high-severity vulnerabilities in entrypoint.sh:

1. github-env-injection (lines 97-99): Replaced the static 'EOF' heredoc delimiter with a cryptographically random 32-character hex string generated by `openssl rand -hex 16`. The new pattern uses `printf 'MLC_OUTPUT<<%s\n' "$_mlc_delim"` and `printf '%s\n' "$_mlc_delim"` to safely write the multiline GITHUB_ENV value. This prevents heredoc injection where attacker-controlled content in error.txt containing a line 'EOF' could terminate the heredoc early and inject arbitrary environment variables.

2. script-injection (line 143): Removed the `COMMAND="${FIND_CALL[*]}"` / `$COMMAND &>> error.txt` pattern and replaced it with `"${FIND_CALL[@]}" &>> error.txt`. Using the array directly with proper quoting prevents word splitting and shell metacharacter injection from user-controlled inputs (BASE_BRANCH, FILE_EXTENSION, FOLDER_PATH) that were incorporated into the FIND_CALL array.
